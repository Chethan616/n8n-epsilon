ServiceNow Incident Table API — CLI cheat sheet (Windows PowerShell)
=======================================================================

Written for PowerShell specifically. Two gotchas that will break this if
ignored:
  - PowerShell's `curl` can be an alias for Invoke-WebRequest, which does
    NOT understand real curl flags (-H, -u, -G, --data-urlencode). This
    machine resolves plain `curl` to the real C:\Windows\System32\curl.exe,
    but if yours doesn't, use `curl.exe` explicitly everywhere below.
  - JSON request bodies MUST be written to a file withOUT a UTF-8 BOM.
    `Out-File -Encoding utf8` adds a BOM and ServiceNow will reject the
    payload as "not valid JSON". Use the WriteAllText pattern below instead.


0) SETUP — run this once per PowerShell window
--------------------------------------------------
Loads SERVICENOW_INSTANCE_URL / SERVICENOW_USERNAME / SERVICENOW_PASSWORD
from .env into this session's environment variables. Variables set this way
persist for the rest of this PowerShell window (but not in a new one — run
this again if you open a fresh terminal).

  Get-Content D:\epn8n\.env | ForEach-Object {
      if ($_ -match '^([A-Za-z_][A-Za-z0-9_]*)=(.*)$') {
          [System.Environment]::SetEnvironmentVariable($matches[1], $matches[2])
      }
  }

After this, every command below works for the rest of the session.


1) LIST incidents (find one, or see what's open)
-------------------------------------------------
Unresolved incidents only, newest first:

  curl.exe -s -u "${env:SERVICENOW_USERNAME}:${env:SERVICENOW_PASSWORD}" `
    -H "Accept: application/json" `
    "$env:SERVICENOW_INSTANCE_URL/api/now/table/incident" `
    --data-urlencode "sysparm_query=stateNOT IN6,7,8^ORDERBYDESCsys_updated_on" `
    --data-urlencode "sysparm_fields=sys_id,number,priority,state,short_description" `
    --data-urlencode "sysparm_display_value=all" `
    --data-urlencode "sysparm_limit=50" `
    -G

Just our test incidents (filter by the tag used when creating them):

  curl.exe -s -u "${env:SERVICENOW_USERNAME}:${env:SERVICENOW_PASSWORD}" `
    -H "Accept: application/json" `
    "$env:SERVICENOW_INSTANCE_URL/api/now/table/incident" `
    --data-urlencode "sysparm_query=short_descriptionLIKEn8n-epsilon test" `
    --data-urlencode "sysparm_fields=sys_id,number,priority,state,short_description" `
    --data-urlencode "sysparm_display_value=all" `
    -G

Tip: pipe to `ConvertFrom-Json | Format-Table` instead of reading raw JSON,
e.g. add this after the command: `| ConvertFrom-Json | Select -Expand result | Format-Table number,priority,state`


2) GET one incident by number (to find its sys_id for update/delete)
----------------------------------------------------------------------
Replace INC0010006 with the number you want:

  curl.exe -s -u "${env:SERVICENOW_USERNAME}:${env:SERVICENOW_PASSWORD}" `
    -H "Accept: application/json" `
    "$env:SERVICENOW_INSTANCE_URL/api/now/table/incident" `
    --data-urlencode "sysparm_query=number=INC0010006" `
    --data-urlencode "sysparm_display_value=all" `
    -G

PATCH/DELETE need the sys_id (a long hex string) from this response's
"sys_id" field, not the INC number.


3) CREATE a new incident (POST)
---------------------------------
Priority is NOT set directly — ServiceNow calculates it from impact x
urgency. Use the combinations below for a specific priority:

  Critical (priority 1): "urgency": "1", "impact": "1"
  High     (priority 2): "urgency": "2", "impact": "1"
  Moderate (priority 3): "urgency": "2", "impact": "2"
  Low      (priority 4): "urgency": "3", "impact": "3"

  $json = '{"short_description":"Production application unavailable","urgency":"1","impact":"1"}'
  [System.IO.File]::WriteAllText("$env:TEMP\body.json", $json, (New-Object System.Text.UTF8Encoding $false))

  curl.exe -s -m 60 -u "${env:SERVICENOW_USERNAME}:${env:SERVICENOW_PASSWORD}" `
    -H "Content-Type: application/json" -H "Accept: application/json" `
    -X POST "$env:SERVICENOW_INSTANCE_URL/api/now/table/incident" `
    --data-binary "@$env:TEMP\body.json"

Response includes the new record's "sys_id" and "number" — save the sys_id
if you plan to update or resolve it next. Creation can be slow on a PDI
(business rules run synchronously); -m 60 gives it a long enough timeout.


4) UPDATE an incident (PATCH) — change priority, description, etc.
----------------------------------------------------------------------
Replace <SYS_ID> with the sys_id from step 2 or 3. Only include the fields
you want to change:

  $json = '{"short_description":"Updated description here","urgency":"2","impact":"1"}'
  [System.IO.File]::WriteAllText("$env:TEMP\body.json", $json, (New-Object System.Text.UTF8Encoding $false))

  curl.exe -s -u "${env:SERVICENOW_USERNAME}:${env:SERVICENOW_PASSWORD}" `
    -H "Content-Type: application/json" -H "Accept: application/json" `
    -X PATCH "$env:SERVICENOW_INSTANCE_URL/api/now/table/incident/<SYS_ID>" `
    --data-binary "@$env:TEMP\body.json"

State values: 1=New, 2=In Progress, 3=On Hold, 6=Resolved, 7=Closed, 8=Cancelled
(change just the state the same way, with `$json = '{"state":"2"}'`)


5) RESOLVE an incident (PATCH with a valid close_code)
---------------------------------------------------------
close_code is a choice list — allowed values differ per instance. Look
them up first:

  curl.exe -s -u "${env:SERVICENOW_USERNAME}:${env:SERVICENOW_PASSWORD}" `
    -H "Accept: application/json" `
    "$env:SERVICENOW_INSTANCE_URL/api/now/table/sys_choice" `
    --data-urlencode "sysparm_query=name=incident^element=close_code" `
    --data-urlencode "sysparm_fields=label,value" `
    -G

Then resolve, using one of the values that came back (this instance uses
"Solution provided"):

  $json = '{"state":"6","close_code":"Solution provided","close_notes":"Resolved for testing"}'
  [System.IO.File]::WriteAllText("$env:TEMP\body.json", $json, (New-Object System.Text.UTF8Encoding $false))

  curl.exe -s -u "${env:SERVICENOW_USERNAME}:${env:SERVICENOW_PASSWORD}" `
    -H "Content-Type: application/json" -H "Accept: application/json" `
    -X PATCH "$env:SERVICENOW_INSTANCE_URL/api/now/table/incident/<SYS_ID>" `
    --data-binary "@$env:TEMP\body.json"


6) DELETE an incident (cleanup — use sparingly)
---------------------------------------------------
Only for cleaning up test data you created. There is no undo.

  curl.exe -s -u "${env:SERVICENOW_USERNAME}:${env:SERVICENOW_PASSWORD}" `
    -X DELETE "$env:SERVICENOW_INSTANCE_URL/api/now/table/incident/<SYS_ID>" `
    -w "`nHTTP_STATUS:%{http_code}`n"

204 = deleted successfully.


Reference
-----------
Endpoint pattern : https://<instance>/api/now/table/<table>
Table used       : incident
Auth             : HTTP Basic (user:pass, base64-encoded in the Authorization header)
Note             : this instance required granting the user the
                   snc_basic_auth_api_access role before Basic Auth worked
                   (System Security's "Basic Auth Restriction" feature) —
                   see docs/architecture.md / study-guide.pdf for details.

All commands in this file (list, get, create, update) were tested directly
in PowerShell against the live instance before this file was written.
